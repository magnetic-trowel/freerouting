# PCBench hard boards: Freerouting `master-edffcabb`

The 314 PCBench boards that Freerouting **2.5.0 or 2.6.0-RC4** failed on, rerun with `master-edffcabb` (magnetic-trowel/freerouting). This folder keeps every board that still fails, with its routed output, Freerouting's result file and pictures, so the next round of router work can start from it without rerunning anything. Generated by `scripts/pcbench/hard_boards_report.py`.

| File | What |
|---|---|
| `README.md` | This summary |
| `LAYOUTS.md` | All boards with KiCad DRC counts, routed vs human reference |
| `boards/<board>/` | Each failing board: `README.md`, `result.json` (the routed `master.ses` and the `master.png` / `reference.png` renders stay on the benchmark host: third-party boards) |
| `drc-summary.json` | KiCad DRC counts per board and every open connection KiCad reports |

## How results are judged

- **Benchmark clean** (the runner's criterion, also used to choose the boards): exit state COMPLETED, 0 unrouted connections, 0 router-introduced clearance violations.
- **Failing** (stricter): not benchmark clean, or any clearance violation at all, even ones already in the input. Boards failing only for that reason are *pre-existing clearance only*: not routing failures.
- Categories, most severe first: **timeout**: hit the 6 h job budget before the router finished; **unrouted**: router finished but left connections open; **router violations**: fully routed but the router added clearance violations; **pre-existing clearance only**: fully routed and the router added nothing; every violation was already in the input (the runner calls these CLEAN).

### Strategies inside the routing fallback ladder

When the default route leaves connections open, the router first keeps routing that result (`continue`), then reroutes from scratch with each alternative (`direct-first, fanout-retry, short-escape, open-escape, no-fanout`) and keeps the best (`RoutingFallback.java`, `RoutingFallbackRunner.java`). Recorded on 167 boards; boards that route cleanly by default have no ladder. *Fully routed* = 0 unrouted and 0 new violations; *tied best* = lowest unrouted count on that board.

| Strategy | Boards tried | Fully routed | Tied best | Chosen | Median unrouted | Mean unrouted | Median time |
|---|---|---|---|---|---|---|---|
| continue | 138 | 14 | 88 | 30 | 1 | 1.7 | 0.1 min |
| open-escape | 128 | 5 | 53 | 24 | 4 | 12.3 | 0.4 min |
| direct-first | 152 | 12 | 51 | 28 | 4 | 11.2 | 0.4 min |
| short-escape | 136 | 6 | 43 | 20 | 4 | 16.3 | 0.5 min |
| default | 167 | 0 | 38 | 40 | 3 | 10.8 | 0.5 min |
| no-fanout | 122 | 4 | 37 | 14 | 5 | 10.1 | 0.4 min |
| fanout-retry | 138 | 1 | 26 | 11 | 8 | 32.7 | 0.4 min |

No single strategy wins everywhere, so choosing per board, or combining strategies, is the obvious lever.

## KiCad DRC finds problems the benchmark metrics miss

Each routed `.ses` was imported into the placed KiCad board and checked with KiCad 10 DRC against the board's own design rules, alongside the human layout. Of 314 boards, the routed result has **more** violations than the human layout on: clearance 29, hole_clearance 29, shorting_items 17, tracks_crossing 2, copper_edge_clearance 88. **46 benchmark-clean boards** are worse than the human layout under KiCad DRC, so 'clean' means clean by Freerouting's own checks only.

Spot-checked causes (real defects in the routed boards, not artifacts of the import):

- **copper_edge_clearance**: boards often require 0.5 mm, Freerouting used `copper_to_edge_clearance_um = 250` (CAL430FR_CAL430F: a via 0.33 mm from the edge). The DSN export omits copper-to-edge clearance (Issue 558, see `scripts/pcbench/README.md`).
- **shorting_items**: tracks through copper text on F.Cu (BMS-bq76940_EvaluationsBoard) and through no-net pads (ATMEGA328-Motor-Board: GND tracks over an unconnected pad of U5). Neither seems to be an obstacle in the DSN the router gets.
- **hole_clearance**: Freerouting ran with `hole_clearance_um = 0`, so KiCad's hole-clearance rule is never checked (sbc_sbc: 199 violations vs 4 in the human layout).

These look fixable in the DSN export or router settings, without better routing. Judge a better router by KiCad DRC too: 0 unconnected, electrical violations no worse than the reference.

## How this was produced

Requirements: JDK 25 with `java` on PATH, **Python 3.12+** for the runner, KiCad 10 (kicad-cli and Python with pcbnew) and `cairosvg` for the pictures.

```bash
./gradlew --no-daemon executableJar
python3 scripts/pcbench/make_hard_board_subset.py --out build/pcbench-hard-boards/PCBench
python3.12 scripts/pcbench/run_corpus_benchmark.py --jar build/libs/freerouting-current-executable.jar \
    --fixtures-dir build/pcbench-hard-boards/PCBench --tier All --workers 8 --version-label master-edffcabb
python3 scripts/pcbench/collect_hard_board_failures.py --label master-edffcabb \
    --fixtures build/pcbench-hard-boards/PCBench --loop 600   # optional, while the run is going
scripts/pcbench/render_layout.sh <board_id> master-edffcabb      # once per board
python3 scripts/pcbench/hard_boards_report.py --label master-edffcabb
```

- Selection: boards whose 2.5.0 or 2.6.0-RC4 run had unrouted > 0, router-introduced violations > 0 or a non-COMPLETED state: 323 board ids, of which 9 are no longer in the catalog (TMC261-stepstick_TMC261-stepstick-v1, eeg_brainboard_wearable, karabas-nano revA/revB/revC, kitspace_d20_tri_r0.2/r0.3, mechkeys_lfk_revc, wavegen_waveform-generator), leaving 314. Tier E is not part of `--tier All`.
- Run: one runner, 8 workers, `--router.max_threads=1`, `-Xmx4g`, the default 6 h per-board budget, on a 128-thread Linux machine. It took about 17 h; the last hours were a few 1-6 h boards with most workers idle.
- Pictures and KiCad DRC: `render_layout.sh` on every board (about 35 s each, one core).

## What didn't work

- `run_corpus_benchmark.py` needs Python 3.12+: line 1084 nests the same quote type inside an f-string, a `SyntaxError` on 3.10. It also calls plain `java`, so a JDK must be on PATH.
- The runner's last step runs `powershell ... run-benchmarks.ps1 -ReportOnly` (line 1590), which raises `FileNotFoundError` on Linux. The run exits 1 after `benchmarks.json` is complete; `benchmarks.md` and the charts were not regenerated.
- The runner rewrites `benchmarks.json` with `indent=2` (line 1102), doubling the 75 MB single-line file the repo keeps. The committed file is the original bytes with the new runs appended in compact form.
- `import_specctra_ses.py` creates a `wx.App` and fails without an X display ("Unable to access the X Display"). `kicad_layout_tool.py import` does the same import without wx and works headless.
- Running KiCad DRC or plotting directly on the fixture boards writes a `.kicad_prl` next to each one; `render_layout.sh` now works on a temporary copy.
- Five failing boards wrote 2.6-12 GB logs (33 GB in total), over 99.8% of it the same `Polyline: must contain at least 2 different points` warning (`geometry/planar/Polyline.java:36`), with no net or location. These are among the slowest boards, so the degenerate polylines are worth investigating as a routing lead. The runner now collapses repeated messages when each board finishes (`compact_log.py`, `--keep-raw-logs` to opt out).
- A single N-worker runner leaves workers idle on the long tail. The boards are independent: next time, run one job per board (1 core, ~5 GB) or several runners on disjoint subsets in separate clones (the runner takes a lock per clone).
